# Обновление фронтенда SoftSkills CRM

База изменений: main, c6b8b287c9557b9c5c24f67f2807ff20723b2fc9.
Обновлять frontend и backend вместе. Изменения не опубликованы на сервере.

## Исправления

- Исправлен регистр Registration; build проверяет TypeScript и не использует Unix-команду cp.
- app: маршруты, AuthProvider и проверка сессии. Layout общий для CRM и карточки клиента.
- features: клиенты, группы, сотрудники, лиды, расписание, финансы, аналитика и импорт.
- Формы групп/сотрудников/лидов отделены от таблиц; состояние и обработчики вынесены в feature hooks.
- shared: единый API-клиент, типы, кнопки, уведомления, модалки, состояния ошибок, стили и токены.
- Разделы имеют URL. Перезагрузка сохраняет раздел, возврат из карточки ведёт к клиентам.
- Убран глобальный перехват fetch и X-Session-ID. Сессия передаётся cookie только запросам CRM.
- Ошибки HTTP не считаются успешным сохранением. Неуспешное сохранение клиента оставляет форму открытой.
- Удаление клиента отправляет cookie, запрашивает подтверждение и проверяет компанию на сервере.
- Редактирование/удаление клиентов больше не являются независимыми конфликтующими режимами.
- Пополнение выполняется отдельным серверным маршрутом с блокировкой строки и транзакцией баланса + проводки.
- Ручная корректировка баланса использует expected_balance: конфликт возвращает 409 вместо перезаписи нового баланса.
- Расписание сохраняет все шаблоны дня и замещает только совпадающую пару группа/время реальным занятием.
- Расписание учитывает время окончания, отображает ранние/поздние занятия, не создаёт 24:00.
- API расписания возвращает group_id; даты реальных занятий передаются календарной строкой без UTC-сдвига.
- Канбан: все шесть колонок в одной горизонтально прокручиваемой сетке.
- Единые базовые шрифты/цвета; компактная оболочка без вложенной карточки dashboard.
- Мобильное меню с названиями разделов; таблицы и расписание прокручиваются внутри содержимого.
- Общие native-dialog оболочки: фокус, Escape, блокировка фонового интерфейса, возврат фокуса.
- Кнопки вместо кликабельных div в навигации; связаны подписи полей в извлечённых формах.
- Контекстное меню клиента позиционируется относительно viewport, закрывается при прокрутке/Escape.
- Группы клиента выбираются чекбоксами; отрицательный баланс карточки отображается красным.
- Форма входа прокручивается на низком экране и показывает ошибки/ожидание.
- Повторная отправка основных форм заблокирована на время запроса.
- Удалены мёртвые закомментированные JSX-блоки; нормализованы имена файлов и каталогов.

## Запуск

Используйте Node.js 22 LTS (22.12+) или совместимую более новую версию.
Сохраните существующий backend/.env; он не входит в пакет.

Из корня репозитория, в PowerShell или bash:

```sh
npm ci --prefix backend
npm ci --prefix frontend
npm run dev --prefix backend
```

Во втором терминале:

```sh
npm run dev --prefix frontend
```

По умолчанию frontend использует /api, Vite перенаправляет его на http://127.0.0.1:3000.
При другом порте задайте API_PROXY_TARGET в frontend/.env.local по образцу frontend/.env.example.
VITE_API_BASE_URL позволяет явно указать отдельный API-домен. Для cookie-сессии предпочтителен один origin.

Production:

```sh
npm run build --prefix frontend
npm run dev --prefix backend
```

Backend раздаёт frontend/dist и SPA fallback; /api обслуживается API-router.
Если фронтенд раздаёт Nginx, настройте try_files $uri /index.html и proxy /api на backend.
При proxy_pass без удаления /api backend уже поддерживает этот префикс.
Старые API-маршруты без /api сохранены для совместимости.
Это инструкция по сборке/маршрутам, а не настройка production-сессий или полноценное развёртывание.

## Новые API-контракты

POST /api/clients/:id/top-up принимает {"amount": 500}. Минимальный rank 500.
Изменение баланса и financial_transactions коммитятся вместе; ошибка откатывает оба изменения.

PATCH /api/updateclient/:id при передаче balance требует expected_balance.
Пример: {"balance": 1500, "expected_balance": 1000}. При устаревшем балансе — 409.
Поле company_id из тела запроса не меняет компанию клиента.

POST /api/import принимает {"type":"clients|leads|employees", "rows":[...]}.
Проверка всех строк предшествует записи. Ошибка отменяет всю пачку.

## Импорт

Поддерживается .xlsx, первый лист, до 2 МБ и 200 строк данных.
Старый .xls нужно пересохранить как .xlsx. Формулы не принимаются.
Предпросмотр показывает первые пять строк, пароли маскируются.

| Категория | Столбцы | Обязательные | Создание |
|---|---|---|---|
| clients | name, contact | name | Активный клиент с нулевым балансом |
| leads | name, contact, source, description | name, contact | Новый лид |
| employees | full_name, email, password, contact | full_name, email, password | Преподаватель, rank 100 |

Строки создаются заново; обновления существующих записей нет.
Импорт сотрудников доступен только rank >=1000. Пароль: минимум 8 символов, максимум 72 байта.
Повторяющаяся почта сотрудников отклоняет пачку. Контакты храните в Excel как текст.
Для клиентов/лидов повторный импорт создаёт новые записи: после неоднозначного сетевого сбоя сначала проверьте список.
Новые таблицы или миграции схемы для этого обновления не нужны; используются таблицы существующего SqlSchema.sql.

## Проверки и границы проверки

```sh
npm run build --prefix frontend
npm run lint --prefix frontend
npm test --prefix frontend
npm run typecheck --prefix backend
npm test --prefix backend
```

19 frontend-тестов: расписание, API-ошибки, cookie удаления, payload пополнения,
сохранение формы при отказе, маршруты/возврат/перезагрузка, выход, истёкшая сессия,
неуспешный вход, открытие вынесенных форм и пустое расписание.
15 backend-тестов: порядок операций пополнения, rollback, принадлежность клиента,
валидация суммы, сессия и валидация импорта. База в этих тестах замокана.

Сборка, TypeScript, lint и тесты проверены. Chromium в рабочей среде падает при отрисовке;
полноценная визуальная проверка desktop/mobile не завершена. React-сценарии проверены в jsdom.
Не выполнялись запросы к production API, реальные платежи, импорт в настоящую БД или публикация.
Не проверена конкурентность на живом MySQL: транзакционный сценарий проверен с моками.
ExcelJS загружается динамически только при чтении файла; Vite предупреждает о размере его отдельного чанка.

Перед публикацией проверьте на тестовой БД: вход/выход, две параллельные операции пополнения,
расписание с несколькими группами и реальным уроком, импорт одной пачки каждого типа,
модалки и горизонтальную прокрутку на ширине 390px и desktop.
