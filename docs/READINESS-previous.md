# Проверка готовности — 27 октября 2026

Проверен приложенный alpha-crm-finance(1).zip, исправления включены в этот проект.
Основной сценарий проходит целиком на реальной чистой MySQL и production JS-сборке.
Это подтверждение проверенных API-сценариев, а не утверждение полной готовности production-инфраструктуры.

dev/test env, не production .env. Windows: рекомендован Compose из README.

## Основной сквозной сценарий

`backend/test/integration/readiness.test.ts` запускает отдельный процесс dist/server.js
с production-конфигурацией и проверяет реальные HTTP-запросы:

1. Регистрация организации и директора, сохранение companySlug и cookies.
2. Второй филиал и аудитория.
3. Менеджер и преподаватель, реальные входы обоих.
4. Лид.
5. Конвертация в плательщика и отдельного ученика.
6. Группа и зачисление.
7. Занятие с базовой ценой, скидкой, плательщиком и абонементом.
8. Оплата 50000 копеек, параллельный повтор не дублирует её.
9. Проведение учителем; конкурентный запрос с той же ревизией получает конфликт.
10. Проверки: баланс плательщика 41000, кассы 50000, начисление учителю 2000,
    посещение present, остаток абонемента 9.
11. Исправление менеджером на excused с причиной и новой ревизией.
12. Баланс 50000, абонемент снова 10, в истории есть компенсирующая запись.
13. Частичный возврат 5000 с исходной оплатой: баланс 45000.
14. Вход плательщика и ученика, профили, расписание, группы, абонементы;
    запрет зарплаты/комментариев и финансов плательщика для ученика.
15. Preview без созданных людей, подтверждение, параллельный повтор с разными ключами.
    Проверены чужой пользователь, истечение срока и атомарный откат при позднем конфликте контактов.
16. Вторая организация не видит ученика, занятие, счёт и не подтверждает чужой импорт.

Конкурентные проверки: вместимость группы, аудитория с разными преподавателями,
преподаватель с разными аудиториями, повтор оплаты, проведение одного занятия,
повтор подтверждения импорта. Дополнительные старые тесты проверяют денежные возвраты,
компенсации, лимиты, транзакционный откат, роли, ветвление доступа и абонементы.

## Исправления и добавления

- Добавлен отсутствовавший двухэтапный Excel-импорт: сохранённый preview на 24 часа,
  проверка тем же кодом, что и запись; preview откатывает все доменные изменения через savepoint.
- Confirm повторно проверяет текущие конфликты, исполняется атомарно, ограничен автором и организацией,
  повтор с другим ключом возвращает прежний результат. Исправлена обработка MySQL-значения
  `"0"` в проверке истечения: теперь явное числовое сравнение, а не truthiness строки.
- Миграция 008 и readiness для неё. Уже выпущенные миграции не переписаны.
- Добавлены ESLint, проверка типов тестов и основной production API E2E.
- OpenAPI: заменены заглушки ответов импорта, пользователей, справочников, уведомлений,
  виджетов, аналитики и других операций; исправлены attendance DTO, nullable room_id,
  поля кабинетов, общие comments. Единый список portalFields для API и схем.
- Unit-тест сопоставляет все маршруты Express с OpenAPI. Интеграционные помощники
  проверяют фактические успешные ответы по JSON Schema/Ajv. Документированы cookies,
  CSRF, ошибки, пагинация, If-Match, expectedRevision и Idempotency-Key.
- Добавлены Dockerfile, Compose, env.example, генерация случайных локальных секретов,
  явная dev:seed, backup/restore scripts, пример Nginx, Windows/Ubuntu запуск,
  процедуры первого запуска/обновления и frontend-integration.md.

## Что ещё требует настройки и проверки

- Docker Compose **не запускался**: выполнен разбор YAML, но сборку образов и весь стек
  надо проверить на хосте с Docker. Node 22.18.0 из Dockerfile отдельно не запускался;
  фактические тесты выполнены на Node 24.22.1. Nginx и TLS в этой среде не поднимались.
- На сервере нужны домен, сертификаты и их обновление, случайные secrets, HTTPS origin,
  Secure cookies, доверенный proxy, закрытая БД, мониторинг и расписание независимых backup.
  Compose-команды backup.mjs не исполнялись здесь; нативный dump/restore реально проверен.
- Основной frontend не подключён и не тестировался с API. Браузерный E2E через HTTPS не выполнен.
- Нагрузочных тестов нет. Общая блокировка организации сериализует операции и ограничивает throughput.
- Старые MySQL DDL-миграции не гарантируют автоматическое возобновление после сбоя в середине файла;
  порядок действий описан в operations.md. Чистое применение и повтор полностью применённых миграций проходят.
- Подтверждённые импорты и idempotency остаются без автоматического удаления; нужна retention-политика.
- backup.mjs буферизует до 256 MiB; для больших баз нужен потоковый backup.
- Внешний MySQL через TLS пока не настраивается env; текущий Compose использует закрытую локальную сеть.
- В зависимостях остаются предупреждения deprecated; полный аудит уязвимостей не проводился.
  Закреплённые patch-теги образов не заменяют обновления безопасности и фиксацию digest на сервере.
