# Готовность связки frontend / backend

Дата: 28 октября 2026. Этот отчёт заменяет прежний вывод NO-GO из аудита.

## Вывод

Связка реализована и пригодна для развёртывания на тестовом HTTPS-хостинге и приёмки
перед ограниченным рабочим запуском. Блокировавшая запуск зависимость от mock/legacy API
устранена. Известных блокирующих дефектов в проверенных сценариях не осталось.
Это не гарантия отсутствия ошибок во всех возможных операциях и не нагрузочная
сертификация. Фактический VPS, Docker-образы, DNS и доверенный сертификат проверяются
после развёртывания по `DEPLOYMENT.md`.

## Что изменено

- По умолчанию открывается реальный интерфейс `frontend/src/real`, использующий `/api/v1`.
  Старый демоинтерфейс сохранён отдельно; его экраны и локальное хранилище не являются
  рабочим источником данных. Новый интерфейс — ресурсные списки и карточки, а не полная
  визуальная копия прежнего календаря/канбана.
- Регистрация, вход, код организации, сессия, logout, профиль, приглашения и ролевые разделы
  работают через API. CSRF хранится в памяти, сессионный cookie — HttpOnly.
- Люди/контакты, плательщики, ученики, сотрудники, доступы, филиалы, аудитории, группы,
  зачисления, лиды, задачи, абонементы, занятия, учёт денег, отчёты, уведомления и Excel-импорт
  подключены к серверу. Сервер выполняет проверку ролей, филиалов и принадлежности организации.
- Формы генерируются из извлечённого OpenAPI-контракта. Редактирование отправляет версию,
  проведение — revision, финансовые операции и импорт — ключ идемпотентности.
- Деньги переводятся из рублей в целые копейки без округления float. Сохранены подписки,
  фиксированные/процентные скидки при проведении и корректировках. Nullable-окончание
  зачисления не требует искусственной даты. Даты фильтруются в часовом поясе устройства.
- После потери ответа финансовый повтор использует тот же ключ. При неопределённом исходе
  обычной неидемпотентной записи повтор из той же формы блокируется до проверки результата.
- Исправлены предпросмотр импорта (отсутствовавший ключ), отметка уведомлений, вывод денежных
  агрегатов, доступные фильтры. Старые публичные формы покупки тарифов и отзывов не вызывают
  несуществующее API. Текущая лицензия — бесплатная бета.
- Добавлены frontend Dockerfile, локальный Compose frontend и отдельный production Compose
  с HTTPS Nginx, генератор случайных секретов, инструкция запуска и резервного копирования.
- Сохранены исправления предыдущего аудита: запрет приглашений в архивную организацию/филиал,
  logout из архивной организации, корректные 415, regression tests и обновлённые зависимости.
  Все восемь SQL-миграций побайтно совпадают с входным архивом.

## Границы выпуска

- Перед рабочими данными обязательна приёмка на выбранном хостинге: health, TLS, вход,
  основная финансовая цепочка, backup/restore и наблюдение за диском/ошибками.
- Платёжного эквайринга, QR-оплаты, SMS/email-рассылок, оплаты SaaS-подписки и публичных
  отзывов в backend нет. Внутренний учёт оплаты не списывает деньги с банковской карты.
- Не проверены высокая конкурентная нагрузка, многосерверный deployment, внешние интеграции,
  отдельные домены UI/API, все мобильные браузеры и восстановление на конкретном VPS.
- Здесь не выполнена публикация и не установлены пользовательские DNS/сертификаты.
  Пошаговые команды и проверки находятся в `DEPLOYMENT.md`.

## Повторить проверку

Сначала выполнить `npm ci` в обоих проектах, все typecheck/lint/unit/build,
`npm run openapi` в backend и `node scripts/sync-contract.mjs --check` из корня.
Для браузера: `cd frontend && npx playwright install chromium` (на Linux также нужны
системные библиотеки Chromium). Затем из корня:

```sh
RUN_BROWSER_TESTS=true MYSQL_BASE=/usr bash scripts/verify-native.sh
```

Нужна доступная нативная MySQL 8 с mysql/mysqldump/mysqlcheck, свободный loopback-порт 3307,
права запуска отдельного mysqld и OpenSSL. По умолчанию браузерный тест использует встроенный
тестовый HTTPS-прокси. Для настоящего Nginx добавить `NGINX_BINARY=/usr/sbin/nginx` и
`NGINX_MIME_TYPES=/etc/nginx/mime.types`. `CHROMIUM_EXECUTABLE` позволяет указать установленный
бинарник. `SKIP_API_TESTS=true` — только для повторной отладки браузера, не полный прогон API.
Никогда не запускать эти тесты на рабочей БД; требуется имя с суффиксом `_test`.
