# Учебный модуль

Миграция: `006_education.sql`. Применять через `cd backend && npm run migrate` после
настройки `.env`. Предыдущие миграции не изменены. `/health/ready` требует новую миграцию.
Фронтенд не подключался к новым полям в рамках этой задачи.

## Расписание и участники

- `POST /api/v1/lessons`: групповое (`groupId`) либо индивидуальное (`groupId:null`, ровно один ученик) занятие.
- `PATCH /api/v1/lessons/{id}`: полный набор редактируемых полей и `expectedRevision`.
  Используется для переноса, замены преподавателя, изменения состава, плательщиков, цен и скидок.
  Только для `scheduled`; филиал неизменяемый. Удалённые из состава ученики не остаются в посещаемости.
- `GET /api/v1/lessons?from=...&to=...`: обязательные UTC/offset моменты, `0 < to-from <= 93 суток`.
  Выборка занятий, пересекающих `[from,to)`, а не только начавшихся в нём.
  Фильтры `branchId`, `groupId`, `teacherId`, `roomId`, `studentId`, `status`;
  пагинация `page`, `pageSize` (максимум 100), сортировка по разрешённым полям.
- `GET /api/v1/lessons/{id}`: карточка; `GET /lessons/{id}/attendance`: участники с пагинацией.
- `POST /lessons/{id}/cancel`: `expectedRevision`, `reason`, `Idempotency-Key`.
  Отмена проведённого занятия компенсирует финансовые записи и расход абонемента.

Создание и редактирование доступны директору/менеджеру в разрешённых филиалах.
Преподаватель, аудитория, группа, ученик и выбранный плательщик должны соответствовать филиалу.
Плательщик должен быть связан с учеником активной записью `payer-students`.
При отсутствии `payerId` используется основной плательщик ученика с той же проверкой связи.
Группа/ученик/преподаватель/филиал должны быть активны, аудитория не архивирована.
Участники группы должны иметь зачисление, покрывающее всё занятие.
Вместимость группы обязательна; `rooms.capacity:null` означает отсутствие лимита аудитории.

`startsAt`/`endsAt` — ISO 8601 с Z или offset; хранятся в UTC с точностью миллисекунд.
Продолжительность строго положительна и не более 24 часов.
`timezone` — валидное имя IANA (по умолчанию `UTC`) для отображения. Оно не переинтерпретирует
переданный момент; при переходе DST клиент обязан отправить явный offset.
`subject` для группы берётся из группы; противоречащее значение отклоняется.
Для индивидуального занятия задавайте subject явно, если нужен предметный абонемент.

Конфликт определяется `existing.start < new.end AND existing.end > new.start` для аудитории
или преподавателя. Отменённые занятия исключены, соседние интервалы разрешены.
Все API-операции используют InnoDB-транзакцию с `SELECT ... FOR UPDATE` строки организации
**до чтения состояния и проверки расписания**. Поэтому два процесса/соединения не могут
одновременно пройти проверку и назначить конфликтующие занятия. Та же блокировка защищает
переносы, вместимость, исправления и расход последнего занятия абонемента.
Цена этой стратегии для беты — последовательные операции внутри одной организации.
Прямые SQL-записи сторонними процессами должны соблюдать тот же протокол.

## Цены и скидки

`basePrice` занятия — строка целых копеек; значение по умолчанию `"0"` сохраняет совместимость
со старым API, где каждый участник передавал `price`. Новому клиенту следует задавать basePrice явно.
`attendees[].price` необязателен: при отсутствии берётся basePrice; при наличии это индивидуальная цена.
На участнике разрешено **одно** из полей:

- `discount`: фиксированная скидка, строка копеек, не больше индивидуальной цены;
- `discountPercent`: целое количество базисных пунктов, 0..10000 (1250 = 12,50%).

Отсутствие обоих означает нулевую скидку. Одновременная передача даже нулевых значений запрещена.
Вычисления в BigInt. Округление HALF_UP применяется **к итоговой сумме**, один раз:
`payable = (price * (10000 - discountPercent) + 5000) / 10000`, целочисленное деление.
Пример: 101 копейка и 50% → 51 копейка к оплате, 50 копеек фактической скидки.
В БД `discount` всегда хранит фактическую скидку в копейках, `discount_percent` — исходный процент
или NULL для фиксированного типа. Отрицательные цены/итоги запрещены.

## Проведение и финансовая интеграция

`POST /lessons/{id}/complete` с `Idempotency-Key` и телом:

```json
{
  "expectedRevision": 0,
  "reason": "Проведение",
  "attendance": [{"studentId":"UUID","status":"present"}]
}
```

- `present` — присутствовал; `absent` — прогул; `excused` — уважительный пропуск.
- До проведения `attendance:null`. Это не прогул. Необходим ровно весь состав, без дублей.
- До начала занятия проведение запрещено. Преподаватель может впервые провести только своё занятие;
  не может изменять цены, скидки или выбор абонемента. Директор/менеджер могут исправлять проведение.
- Директор/менеджер могут передать на участнике `price`, `discount` ИЛИ `discountPercent`,
  `subscriptionId` (UUID — выбрать, null — перейти на поурочное обучение).
- `conductLesson` — единый сервис; вызывается внутри общей транзакции маршрута.
  Он проверяет ревизию/права/полный состав, компенсирует старые записи при исправлении,
  записывает посещаемость, расход абонементов и **реальные записи `crm_ledger`** через `finance.entry`,
  начисляет зарплату, затем меняет статус/ревизию. Ошибка любого шага откатывает всё.
- Финансовый модуль присутствует в исходном проекте, поэтому интеграция включена, заглушки нет.
  Успешный ответ без необходимых проводок не предусмотрен.
- `present`/`absent` списывают индивидуальную итоговую стоимость с лицевого счёта плательщика
  и одно занятие выбранного абонемента; `excused` не списывает ни деньги, ни занятие.
  Абонемент здесь — количественное право посещения, а не денежный баланс и не подтверждение оплаты.
  Его выдача не создаёт приход денег. Это сохранённая модель финансового модуля проекта.
- Зарплата преподавателю начисляется по снимку salary занятия. Исправления/отмена используют
  компенсирующие записи, а не удаление истории. Повтор ключа идемпотентности возвращает прежний результат.

## Абонементы

- `POST/PATCH /subscription-templates`: branchId, name, subject, необязательный groupId,
  lessons, days, price, active. Управление — директор; groupId должен соответствовать филиалу и предмету.
- `POST /subscriptions`: studentId, templateId, startsAt; выдача — директор/менеджер.
  Количество, предмет и группа копируются в выданный абонемент; срок фиксируется в момент выдачи.
  Изменение шаблона не меняет условия уже выданных экземпляров.
- При ограничении группой и предметом должны совпасть оба. У индивидуального урока groupId:null.
- `GET /subscriptions/{id}/availability`: остаток и доступность сейчас.
- `GET /subscriptions/{id}/usage?page=1&pageSize=25`: история списаний (+1) и возвратов (-1).
- `POST /subscriptions/{id}/freeze` и `/unfreeze`: `{}`, обязательный Idempotency-Key.
  Заморозка только начавшегося, ещё не истёкшего абонемента. Повторная заморозка/разморозка — конфликт.
  Разморозка продлевает срок на точную длительность заморозки в миллисекундах.
- Срок `[starts_at,ends_at)`, заморозка `[starts_at,ends_at)`: начало включено, конец исключён.
  days — ровно 24 часа, не календарные сутки часового пояса.
- Новое списание требует действительности сейчас **и** на начало занятия, отсутствия заморозки сейчас
  и на начало занятия и положительного остатка. Истёкший/исчерпанный/замороженный абонемент отклоняется.
- Исправление/отмена возвращает ранее использованное занятие. Исправление той же ранее оплаченной
  отметки с тем же абонементом сохраняет историческое списание даже после его истечения/заморозки сейчас;
  срок и заморозка на момент урока всё равно проверяются. Это не новое использование остатка.
  Переход с excused на present либо смена абонемента всегда требует текущей доступности.
- Без абонемента допускается обычное поурочное обучение.

Полный контракт — `openapi.json`. Автотесты: `npm test`, `npm run test:integration` с отдельной
MySQL БД, имя которой заканчивается на `_test`.
