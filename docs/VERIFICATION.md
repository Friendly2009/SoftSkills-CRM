## Проверенные сценарии

- Env fail-fast без вывода секретных значений, недоступная MySQL предотвращает запуск.
- /health/live и /health/ready, отсутствие обязательной миграции даёт readiness 503.
- Транзакционная регистрация всех сущностей; искусственная ошибка поздней вставки
  откатывает уже созданную организацию. Нормализация/отклонение телефона.
- Одинаковые название, login и email в разных организациях; companySlug различается.
- Вход по login/email с companySlug; неверный slug/пароль, заблокированный аккаунт.
- CSRF до входа и после входа; поддельный токен, чужой Origin, malformed JSON,
  валидация и запрет лишних полей, allowlist CORS.
- HttpOnly/SameSite/Lax; production Secure/SameSite=None. Cookies проверены на уровне HTTP,
  полноценный browser E2E с TLS не выполнялся.
- Разные токены сессий, выход с очисткой cookie, отзыв остальных сессий,
  истечение сессии, изменение профиля, текущий пароль и отзыв всех сессий при смене.
- Приглашения: чужие person/branch, проверка роли директора, хеш вместо открытого токена,
  параллельное принятие с одним успехом, повтор, истечение и аннулирование старого при перевыдаче.
- Изоляция организаций, филиалов, ролей; пустые служебные branchIds не дают доступа.
- Блокировка отзывает сессии, смена прав отзывает сессии; самостоятельное повышение запрещено.
- Последний директор защищён, маршрут удаления аккаунтов отсутствует;
  при параллельной взаимной блокировке двух директоров остаётся один активный.
- Плательщик видит собственных детей, ученик — себя; DTO скрывают внутренние поля.
  Смешанные teacher+payer сохраняют личный доступ без чужих финансовых данных.
- Rate limit входа и регистрации хранится в MySQL.
- SIGTERM закрывает HTTP и пул, процесс завершается с кодом 0.
- Предыдущие 23 сценария CRM: финансовые проводки, идемпотентность, абонементы,
  расписание, конкурентные операции, импорт, уведомления, аналитика и права.

Лог последнего MySQL-прогона: integration-results.txt.

## Границы проверки

Не выполнялись развёртывание на сервере пользователя, браузерные E2E с реальным TLS,
нагрузочные тесты, независимый аудит безопасности и проверка на пользовательской рабочей БД.
Frontend остался в исходном состоянии; его сборку и тесты в этой задаче не запускали.
Проверка зависимостей npm audit в этой задаче не выполнялась.
Это проверенный backend для интеграции и пилота; тесты не доказывают отсутствие всех ошибок.
