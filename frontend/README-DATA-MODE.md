# Переключение данных нового CRM

В `src/App.tsx` один state управляет режимом всего frontend:

```tsx
const [isMock, setIsMock] = useState(true);
```

- `true`: локальные демоданные; изменения сохраняются в localStorage `softskills.crm.demo.v1`. Backend не требуется.
- `false`: HTTP API; демоданные и их localStorage не используются. Ошибка сервера отображается пользователю, подстановки моков нет.

Смена state размонтирует экраны и отменяет незавершённые запросы. Дизайн нового CRM сохранён. Дополнительного переключателя в интерфейсе нет. Старый `isDebug` не выбирает источник данных.

## Запуск

```sh
npm ci
npm run dev
```

Открыть `/dashboard`. Для HTTP-режима войти через `/authorization` при наличии работающего сервера.
Скопировать `.env.example` в `.env` при необходимости. `VITE_API_BASE_URL` задаёт адрес API (по умолчанию `/api`), но не режим.
Dev-прокси Vite перенаправляет `/api/*` на `API_PROXY_TARGET` (по умолчанию `http://127.0.0.1:3000`) и снимает префикс `/api`. В production нужен аналогичный reverse proxy либо полный URL API с настроенным CORS и cookies.

## Важно: готовность backend

Backend из исходного архива НЕ реализует полный контракт нового CRM ниже. Этот патч добавляет frontend-адаптер, а не недостающие серверные методы. При `isMock = false` и старом backend новый CRM покажет ошибку отсутствующего API. Backend не изменён; сквозная работа с живым сервером не проверялась.

Существующие signin/signup/logout и публичные страницы используют прежние пути через общий адрес API. Подмена глобального fetch удалена. Авторизация нового CRM проверяется сервером на bootstrap; запросы передают cookies (`credentials: include`). Старые файлы `src/crm/requests/*.requests.ts` с `export declare` не используются новым адаптером.

## Контракт HTTP нового CRM

Реализация frontend: `src/crm/data/api.ts`, команды: `commands.ts`, проверка ответа: `validation.ts`.
Все пути ниже относительно `VITE_API_BASE_URL`.

### GET /crm/bootstrap

Возвращает полный снимок разрешённых пользователю данных:

```ts
{ data: MockDatabase, revision: string }
```

`MockDatabase` — историческое имя интерфейса в `src/crm/interfaces/common.ts`; в HTTP-режиме он содержит только реальные серверные данные. Обязательны `version: 1`, массивы сущностей, activity, settings, dictionaries, widgets, notifications, profile и aiBalance согласно TypeScript-интерфейсу. Пустые массивы допустимы. `revision` — непустая строка версии. Используйте интерфейс и валидатор как точную схему, не возвращайте оболочку `{success, data: snapshot}`.

### POST /crm/commands

JSON-запрос:

```ts
{ command: CrmCommand, expectedRevision: string, requestId: string }
```

Успешный ответ — новый полный снимок той же формы, что bootstrap. Интерфейс обновляется только после подтверждения сервера. Повтор одинаковой неудавшейся команды в рамках текущего экрана сохраняет requestId. Сервер должен дедуплицировать requestId, проверять права, валидировать данные и применять изменения атомарно. При конфликте версии вернуть 409; пользователь обновляет страницу. Для финансовых операций дополнительно проверять бизнес-ключ и исключать двойное списание/зачисление на backend.

Поддерживаемые команды (точные поля — в `commands.ts`):

| Команда | Назначение |
| --- | --- |
| record.save | Создать/изменить запись |
| records.import | Импортировать строки атомарно |
| records.status | Изменить статус выбранных записей |
| lead.move | Переместить лид |
| client.topUp | Зарегистрировать оплату клиента |
| lesson.close | Закрыть занятие с посещаемостью |
| activity.add | Добавить комментарий |
| settings.save | Сохранить настройки раздела |
| dictionary.save / dictionary.remove | Изменить справочник |
| profile.save | Сохранить профиль |
| widget.add / widget.remove | Изменить набор виджетов |
| notifications.read | Отметить уведомления прочитанными |
| ai.topUp / ai.report | Пополнить баланс ИИ / создать отчёт |
| license.extend | Продлить лицензию |

ИИ, оплата и лицензия в demo имитируются локально. В API-режиме команды выполняет сервер; платёжная интеграция и генерация ИИ этим frontend-патчем не реализуются.

### GET /logout

Завершает сессию; успешный JSON или 204. После подтверждения открывается главная страница.

### Ошибки

401 — переход к авторизации; 403 — недостаточно прав; 404 — API отсутствует; 409 — конфликт версии. Для других ошибок допускается JSON `{ message: string }`. Невалидный снимок отклоняется. Таймаут — 30 секунд. При потере ответа после записи результат на сервере неизвестен: обновите данные перед дальнейшими действиями.

## Проверки

```sh
npm run typecheck:crm
npm run test:crm
npm run build
```

Тесты проверяют операции демо, интерфейс, HTTP-контракт, ошибки и изоляцию режимов. Это не заменяет проверку с реализованным backend.
